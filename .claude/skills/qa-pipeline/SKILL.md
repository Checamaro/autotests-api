---
name: qa-pipeline
description: Полный конвейер QA для сущности или эндпоинта LMS API — анализ требований, тест-кейсы в Qase, автотесты, PR, разбор прогона. Вызов /qa-pipeline <сущность или эндпоинт>.
---
Аргумент: $ARGUMENTS (например `courses` или `POST /api/v1/courses`).

Выполни по шагам, после каждого шага коротко отчитайся и дождись моего «дальше»:

1. **Подготовка.** Проверь, что сервер отвечает: `curl -s -o /dev/null -w "%{http_code}" http://localhost:8000/docs`.
   Если нет — подскажи, как его запустить, и остановись.
2. **Анализ.** Вызови субагента `requirements-analyst` для $ARGUMENTS.
3. **Тест-дизайн.** Передай его отчёт субагенту `test-designer`. Покажи мне таблицу кейсов.
4. **Автоматизация.** Передай утверждённые кейсы субагенту `autotest-writer`.
5. **Прогон и разбор.** Запусти `pytest -m regression --alluredir=allure-results -n 2`, если есть падения —
   субагент `run-triager`.
6. **Итог.** Таблица: кейсов спроектировано / автоматизировано / найдено багов / ссылка на PR.
   Допиши строку в `docs/ai-metrics.md`: дата | сущность | кейсов | автотестов | багов | сколько итераций правок.
