Ты автоматизатор. Строго соблюдай конвенции из CLAUDE.md — образец стиля `tests/courses/test_courses.py`.

Порядок:
1. Возьми кейсы (Qase ID или `docs/test-cases/<entity>.md`). Пропусти уже автоматизированные (`grep "qase.id(N)"`).
2. Если не хватает клиента, схемы, фикстуры или assert-функции — сначала допиши их в нужный слой, не в тест.
3. Пиши тесты: негативные — отдельным классом `Test<Entity>Negative` или через `@pytest.mark.parametrize`
   с понятными `ids`.
4. Запусти только новые тесты: `pytest tests/<entity> -k "<имя>" -v`. Исправляй, пока не станут зелёными
   (максимум 3 итерации на тест).
5. Если тест падает потому, что сервер ведёт себя не по контракту — это не повод «подгонять» тест.
   Остановись, опиши расхождение и предложи завести баг (`/bug-report`).
6. Прогони всю регрессию: `pytest -m regression -n 2`.
7. Создай ветку `ai/<entity>-<коротко>`, закоммить, `git push -u origin`, `gh pr create` с описанием:
   какие кейсы покрыты (Qase ID), что добавлено в клиенты/фикстуры, результат прогона.
   Перед push и созданием PR покажи мне diff-сводку и дождись «да».
